Most AI projects stall on the data, not the model.

Data-to-AI Foundations is an open reference implementation of the layer in between. It builds one checked, aligned foundation from operational data as it really arrives, then prepares that foundation for each downstream use: a dashboard, a forecasting model, an AI assistant. The parts that repeat are written once; the parts that differ are configuration.

The layer every AI project rebuilds

An organization with sensors, test equipment, or business systems usually has the data an AI application needs. What it lacks is a dependable path from those systems to the model: readings on different schedules and in different units, gaps, faults, duplicates, and no record of what was thrown away or why.

That path is usually built twice over: once for each industry, and again within each organization for each kind of downstream use. A dashboard, a forecasting model, and an AI application each need the data in a different state, so the same sources are often extracted, cleaned, and aligned several times. This project separates those two dimensions, and shows the result working in two very different settings.

One foundation, prepared for each use

The same 48 hours of pond data, including the 90-minute oxygen outage, delivered three ways from one foundation built once.

Analytics dashboard

192 rows

Every 15-minute step. The outage stays visible as a gap on the chart, and slow-changing pH may be carried across a two-hour gap.

Forecasting model

180 rows

Only complete rows. The 12 incomplete steps are held back with their reasons, and no oxygen value is invented.

AI assistant

1 row

The current state of the pond at 23:45, with a low-oxygen flag, so the assistant answers questions about right now.

Each use is a readiness profile in the configuration: how far gaps may be filled, which values must be present, how fresh the data must be, and whether the use needs history or only the latest state.

One sequence for every domain

Every pipeline runs the same steps, in the same order. The first five build the shared foundation once; the last three run for each readiness profile. The code for all of them is shared.

  1. ReadCSV connectors, time parsing, column mapping
  2. De-duplicaterepeated records set aside with a reason
  3. Check sourcesimpossible values stopped at the door
  4. Alignone grid per entity, gaps kept as gaps
  5. Joinlookup tables such as a product master
  6. Fill and deriveas far as each use allows; unit conversions, flags
  7. Check for the usewhat this use must and must not receive
  8. Deliver and reportone table per use, quarantine, run report

Every run explains itself

Each run writes a report alongside the table: how many rows each source sent, how many were held back and for what reason, how fresh the result is, and whether the run passed. When a forecast looks wrong, the first question is whether the data were, and the report answers it.

Run it

Python 3.11 or later. Nothing to install: the core uses only the standard library, so the patterns are easy to read and adapt.

git clone https://github.com/yang00333/data-to-ai-foundations.git
cd data-to-ai-foundations
PYTHONPATH=src python -m d2ai run configs/aquaculture.toml
PYTHONPATH=src python -m d2ai run configs/semiconductor_test.toml
python -m unittest discover -s tests

To add a domain, copy a configuration, describe your sources and rules, and run it. If a rule cannot be expressed, that is the signal the shared core needs a new capability.

About

Data-to-AI Foundations is maintained by Yang Chen, a data and AI infrastructure engineer. I have built this layer in semiconductor testing, commercial data products delivered to customers' own data warehouses, and agricultural sensor data feeding production AI. This project collects the parts that kept repeating, in a form anyone can read and run.

Questions, ideas, or a domain you would like to see: open an issue on GitHub.

All data in the project are synthetic; nothing comes from any employer, client, or customer. Code under the MIT License. Source on GitHub.
